### 1. 决策树分析

#### 🎯 决策问题
在检测到 EventUnit 标题与来源内容完全背离（Title Mismatch）且来源不可信（Unresolved URL, Horizon Only）的情况下，选择哪种处置策略以最大化知识系统的长期健康度并最小化错误传播风险？

#### 💰 决策约束
-   **准确性优先**：自生长知识系统的核心是事实准确性，错误数据比无数据更危险。
-   **来源状态**：当前来源为 `horizon_summary_only` 且 `unresolved`，不具备作为“事实”依据的效力。
-   **时间成本**：审计和重新检索会消耗时间，但错误入库的修复成本极高。

#### 🌲 决策树结构

```
                              ┌─ 发现并阻止错误传播 (90%) → 系统完整性保留 (+50)
                    ┌─ 选项1: 隔离与审计 ─┤
                    │                   └─ 审计耗时/资源消耗 (10%) → 短期延迟 (-10)
                    │
                    │                   ┌─ 生成错误知识 (40%) → 知识污染 (-100)
              ─┬─ ├─ 选项2: 强行修正 ─┤
                │  │                   ├─ 偶然正确 (10%) → 系统正常 (+20)
                │  │                   └─ 引入幻觉/错误事实 (50%) → 信任危机 (-80)
                │
                │                   ┌─ 获得正确来源 (60%) → 事件完成 (+30)
                └─ 选项3: 等待补充 ─┤
                                    └─ 持续缺失 (40%) → 任务搁置/失败 (0)
```

#### 📊 详细节点分析

**选项1：隔离与审计（推荐）**
*   **动作**：将 `EVT-20261127-000064` 标记为 `Data_Mismatch_Error`，阻止进入知识图谱，触发日志记录，并尝试重新检索正确的“普法”来源。
*   **期望值计算**：
    *   成功阻止错误：概率 90% × 收益 +50（保护系统可信度） = +45
    *   资源消耗：概率 10% × 损失 -10（审计时间） = -1
    *   **期望值 (EV)** = **+44**
*   **风险分析**：主要风险是审计过程复杂，可能导致短期任务堆积。但这是控制风险的最佳方式。

**选项2：强行修正/猜测**
*   **动作**：忽略来源错误，根据标题生成普法内容，或忽略标题，根据来源生成银行内容。
*   **期望值计算**：
    *   生成错误知识/幻觉：概率 40% × 损失 -100（严重污染） = -40
    *   引入错误事实：概率 50% × 损失 -80（信任损害） = -40
    *   偶然正确：概率 10% × 收益 +20 = +2
    *   **期望值 (EV)** = **-78**
*   **风险分析**：极高。直接违反“不得编造事实”的原则，且来源本身不可信（Unresolved），强行基于其生成内容属于高风险幻觉行为。

**选项3：等待补充**
*   **动作**：不做任何处理，标记为 `Pending_Source`，等待外部输入。
*   **期望值计算**：
    *   获得正确来源：概率 60% × 收益 +30 = +18
    *   持续缺失：概率 40% × 收益 0（无进展） = 0
    *   **期望值 (EV)** = **+18**
*   **风险分析**：较低风险，但效率低下。如果不主动审计，数据映射错误的根本原因未被解决，未来可能复发。

#### 🏆 决策树结论
**最优路径：选项1（隔离与审计）**
理由：在知识系统中，**防止错误比追求速度更重要**。选项1通过阻断错误数据流，保护了系统的核心资产（准确性），其期望值显著高于其他选项。选项2是不可接受的，因为它违背了“严格依据输入内容，不得编造事实”的指令。
